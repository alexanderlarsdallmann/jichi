# Code of conduct

## The short version

Be decent. Assume the other person is trying to get something right.

## What is expected

This is a small project with one maintainer, a public issue tracker, and a
documentation set that records its own mistakes on purpose. The conduct that fits
it is the conduct the documentation already models:

- **Say what you measured, and what you did not.** "I did not test that" is a
  contribution. A confident guess presented as a result is not.
- **Criticise the work, not the person.** A defect report is about a program.
- **Accept a "no" with its reason.** Not every request fits the project, and
  [`docs/DECISIONS.md`](docs/DECISIONS.md) exists so a refusal comes with an
  argument you can disagree with rather than a shrug.
- **Be patient about response times.** One person, in a timezone, with other
  obligations.

## What is not acceptable

Harassment, personal attacks, discriminatory or demeaning remarks, deliberate
intimidation, sustained disruption, publishing someone's private information, or
unwelcome attention of a sexual nature. This applies in issues, in code review, in
commit messages, and anywhere else the project is being conducted.

## Reporting

Raise it with the maintainer privately — the address is the one on the commits in
this repository. Reports are handled discreetly and the reporter's identity is not
shared without their agreement.

The maintainer will respond, and may warn, edit or remove contributions, or block
an account. There is no committee and no appeals process to pretend otherwise
about; if you think a decision was wrong, say so and it will be reconsidered.

## Scope

Project spaces, and any place where someone is representing the project.

*Written for a project this size rather than adopted wholesale from a template.
If a situation arises that this page does not cover, the first paragraph governs.*
