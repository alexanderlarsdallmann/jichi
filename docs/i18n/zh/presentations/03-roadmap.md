# jichi

### 它去过哪里、要去哪里，以及它是如何构建的

---

# 它是如何构建的

- **里程碑，而非大爆炸。** M1（骨架） → 稳步的能力攀升 →
  今天的 **M173**，横跨六个阶段（基础 → 协议 → 自主 →
  加固 → 发布 → 发布后纵深）。
- 每个里程碑都是一个聚焦的计划；设计 + 影响记录在
  `docs/ROADMAP.md`（顶部有一个**主题化索引**）中，对新颖工作还有一份
  `docs/proposals/*.md`。
- 每个里程碑落地都带 **测试** 和 **零警告**——套件为
  **11,000+ 项检查**，随每个特性增长，藏在一个经裁定把关的 `make ci` 之后。

---

# 能力地图（全部已交付）

- **核心与上下文：** 循环、两个提供方、压缩、校准、prompt 缓存。
- **编辑：** 弹性/模糊补丁、原子多编辑、统一 diff。
- **知识：** 混合 RAG（BM25 + 嵌入 + rerank）、docs 索引、PDF、RSS。
- **自主：** 封套（预算/验证/编辑范围/日志）、快照、回溯。
- **规模：** 子代理（2 层深）、并行 worktree、一个热守护进程 + 工作者池。
- **集成：** MCP 客户端、ACP 服务端、LSP 导航 + 重构、编辑器。
- **媒体与声音：** 图像/音频生成、转写、播放/录制。
- **安全：** 路径围栏、特权命令关卡、动能关卡——全部被审计。

---

# 自主运维弧线 (M157–M162)

一次无人值守的运行如今是**有界、被观测、被把关、被引导且可查询的**：

| 能力带 | 落地了什么 |
|---|---|
| **M157** 循环 | tmux/systemd/cron 监督者，位于任务队列 + 参考包之上 |
| **M158** 可观测性 | `runs` / `audit` 读取器；`doctor --unattended` 关卡；文档↔标志 lint |
| **M159/M162** 控制 | 运行中的 unix socket：`status` / `inject` / `pause[--extend]` / `resume` / `abort` |
| **M160** 机器可读 | `--since` 时间窗 + 为 `runs`/`audit` 提供 `--output json` |
| **M161** 溯源 | `runs` 标记一次由操作员**引导**过的运行 |

每一次干预都留下痕迹；每一道痕迹都有一个读取器。

# 向物理世界的触达 (M163)

jichi 作为一个机器人的**思辨心智**——传感器、执行器、声音、舰队：

- **设备即工具**（讲 JSON 的 user-tools / MCP 服务器）；jichi 不链接任何
  设备库（shell-out，就像 `pdftotext`）。
- **动能关卡**——任何移动质量/能量的东西都是 `kinetic: true`，被把关于
  **权限裁定之下**（一次全面自动批准无法满足它），对急停采取白名单优先、
  shell 绕过做影子匹配、始终被审计。
- **声音 I/O**——通过配置的命令实现 `play_audio` / `record_audio`。
- **诚实的边界：** jichi 是**秒级**层；反射 + 真正的急停位于它之下、在固件里。
  已对着一个模拟器验证；硬件延后。

# 自我改进带 (M100+)

设计于 `docs/SELF_IMPROVEMENT.md`：

- **守护进程**——热进程，有界工作者池。
- **Assign/grade 装置**——机器可校验的评估。

主题：一个在*这个*项目上*可度量地*变得更好的编程代理。

# 我们靠自用学到了什么

来自 `docs/ANECDOTES.md`——每一条都是一个教会了持久教训的 bug：

- 把可观测性放在快照/回退的爆炸半径**之外**。
- 预算耗尽应当**停止**，而非**丢弃**——先验证，再保留绿色。
- 一句"做不到"往往是缺少一个工具**广告**，而非缺少一项能力
  （toolProfile 关卡）。
- **对提交裁定把关，而非对日志尾巴**——一个看起来绿色的提交曾经藏了一个红色
  套件（ANECDOTES #17）；提交现在是 `make ci && …`。

# 这是如何构建的——四种交付模式

针对**相同 M1–M173 范围**的人类工作量（人-月；参见
`docs/PROJECT_TIMELINE.md`）：

```
AI-assisted (1 dev + AI)  |  ~1    (actual -- ~5 weeks, 19 active days)
Expert solo               |####################  ~21   (~20-26 months)
Team of ~6                |######################################  ~40  (~5-6 months)
Junior solo               |#########################################################  ~60  (~5-6 yrs)
```

AI 辅助这一条是**人类**监督时间（设计、评审、引导）——
它不含模型算力。教训不是原始速度；而是*人类时间去了哪里*。

---

# 人类实际做了什么（AI 辅助）

开发者几乎没写 C。稀缺资源上移到了**栈的上层**：

- **方向 + 需求**——选择下一个能力带（约 30%）。
- **设计评审**——在代码之前批准每一份 `docs/proposals/*.md`（约 25%）。
- **审阅 diff + 运行中引导**——抓住错误的假设（约 25%）。
- **排序 + 优先级**（约 12%）· **验证 CI**（约 8%）。

> AI 压缩了*实现 + 测试 + 文档*；**设计与监督仍属人类——并设定了质量的上限。**

---

# 指导接下来该做什么的原则

1. **先正确，再谈成本。** 激进地验证；只回退红色。
2. **小面、可组合。** 新特性复用既有的关隘点。
3. **一切可离线测试。** 纯核心 + 薄 I/O 外壳。
4. **从日志中学习。** 代理自己的遥测就是路线图的输入。
5. **新颖之物得有一份提案。** 无参考可抄 → 先用文字把它设计出来。
