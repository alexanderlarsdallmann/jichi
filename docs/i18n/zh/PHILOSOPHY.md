# jichi 的哲学

本仓库的大多数文档讲的是*怎么做*，这一页讲的是*为什么*——一个用 C89 从零重写
的 AI 编程代理背后的原则，以及它所欠下的种种恩情。这是一篇随笔，不是参考手册；
这里没有任何内容像 [CONTRIBUTING.md](../../../CONTRIBUTING.md) 那样具有规范
效力。但如果哪个设计决定看起来武断，这里就是它被作出时所处的思想框架。

## 温故知新 —— 温习旧的，方知新的

「温故知新」（日语读作 *onkochishin*）源自《论语》「温故而知新」——温习旧学，
而得新知。

关于这个项目，最显而易见的问题是：在 Rust 和 TypeScript 的时代，为什么选 C89？
答案不是怀旧。C89 是现存实现最广泛的编程语言标准。一个严守它的程序——不用
`//` 注释、声明置于块首、不用 `long long`、字符串字面量拆分在 509 字符以内——
能在 npm 生态从未听说过的机器上编译：一台用了十年的实验室电脑、一台大学的共享
登录主机、一间没有预算的教室里的单板机。约束本身就是特性。一个*为学习而生*的
代理工具，如果学习者的机器跑不动它，就没有多少价值。

还有第二个、更安静的理由。计算领域最新的事物——一个对代码进行推理的大语言
模型——恰恰被我们最古老的那些纪律伺候得最好：有界缓冲区、显式所有权、用状态码
而非异常、以管道和进程组合起来的小工具。这个代理循环像 1985 年的 UNIX 程序
那样 fork、开管道、`select`。温习旧的，正是新的得以建成的方式。

## 職人気質 —— 职人气质，匠人的秉性

「职人气质」（職人気質，*shokunin kishitsu*）指的是一种态度：把精进手艺当作
对作品本身的义务，而不是做给观众看。职人无论有没有客人要来，都会把作坊的
地板扫干净。

在这个代码库里，扫干净的地板长这样：在 `-std=c89 -pedantic -Wall -Wextra` 下
永远零警告，CI 中开启 `WERROR=1`；一万多条可离线运行的单元检查，让火车上
的贡献者也能信任测试套件；provider 的流式解析靠喂入合成的 SSE 事件来测试，
而不是真去调网络；每一个 `cJSON_Parse` 都有配对的 `cJSON_Delete`；面向不可信
字节的解析器另有一层模糊测试。这一切在演示里都看不见。到了第三年，全都看得见。

匠心也意味着对工具做了什么保持诚实。工具错误一律作为值返回，绝不当作控制流。
一个在迭代上限处停下的子代理会明说——「[stopped at its iteration limit]」——
而不是把残缺的答案冒充成完整的。`docs/i18n/` 下的日文和中文翻译在母语者审校
之前都标注为*初稿*，因为一份自信满满的错误翻译，比一份坦承不足的翻译更糟。

## 改善与守破離 —— 小步前行，与学习的形状

「改善」（*kaizen*）是靠积累实现的进步。这个项目从未重写过；它只有一个个
里程碑——从 M0 的骨架到 M134 的加固——每一个都小到可以审阅、测试，必要时回退。
[ROADMAP](../../ROADMAP.md) 是这份积累的实验笔记，而
[ANECDOTES.md](../../ANECDOTES.md) 记录着值得铭记的失败，因为被研究过的错误
是一课，被遗忘的错误是一次预演。

「守破离」（守破離，*shu-ha-ri*）描述任何一门手艺的学徒如何进阶：**守**，
一丝不苟地守住形；**破**，有意识地打破形；**离**，最终离形而去。本项目的学习
功能正是照这个形状建造的。作业（assignments）板块给初学者以「形」——一份任务
说明、一份评分量表、一架提示阶梯——而学习者层级（`learner-junior|student|senior`）
随着学生的成长逐步撤去脚手架。甚至代理本身在这里也是学生：学习/导师循环读取
自己的遥测数据、起草课程，并且自 M78 起会*纠正*过时的旧课，而不是把新建议
堆在旧建议之上。不能收回的教导是教条；这个循环直到学会收回一课，才算完成。

## 不易流行 —— 不变者与流动者

芭蕉教导他的弟子「不易流行」（*fueki-ryūkō*）：艺术既需要恒常，也需要
流变，而二者归根到底是同一种追求。

这个项目的架构就是这一课的应用。**不易者**：C89、POSIX、arena 分配器、
`jc_status` 契约、一个代理从不窥探其背后的 provider vtable。**流行者**：
每一季都在更迭的模型、端点与协议。二者之间的边界被刻意画好，使流变永远
侵蚀不到内核——代理从不按 provider 分支；新的后端是一个新的 vtable，而不是
一个新的代理。正因如此，同一个二进制既能对话前沿 API，也能跑在你桌边的
llama.cpp 服务器上；也正因如此，当两者都被取代之后，它依然能编译。

## 侘寂 —— 诚实的局限之美

「侘寂」（侘び寂び，或作「诧寂」）在不完美、无常与未竟之中发现价值。软件
文化大多假装事情并非如此；这个代码库尽力不去假装。token 估算是一个字节
启发式，*已知*偏于乐观——所以 M77 让它按模型对照现实自行校准，而不是宣称
一种它并不具备的精确。预算会让运行中途戛然而止，所以 M80 学会了保留未竟的
工作，而不是因为它不完整就付之一炬。每个缓冲区都有界，每个上限都有名字，
输出被截断时，截断处会明说。一个承认自己局限的工具，在局限之内可以被信任；
一个掩饰局限的工具，在任何地方都无法被信任。

## 巨人，与无名者垒成的大地

我们站在巨人的肩膀上——但同样真切地，也站在无数矮人垒起的土丘上：那些没有
留下显赫名字的、数不清的微小贡献。两笔债都是真实的，这个项目对二者同致敬意。

巨人容易叫出名字：C 语言，以及 1989 年将它凝固成全世界都能依托之物的那个
委员会；UNIX 与 POSIX；libcurl，它为人类搬运过的字节，多过我们任何人一生
所能遇见的人；内嵌的 cJSON 的 API 设计；git，它的底层命令默默驱动着快照与
worktree 机制；Language Server Protocol、Model Context Protocol 与
Agent Client Protocol，每一个都是以私利换公器的慷慨之举；
[Continue](https://continue.dev)，本项目重新实现的正是它的 CLI，是它的
设计证明了这个形态值得一造；还有各家模型提供商，是他们的 API 让这个循环
有了对话的对象。

矮人难以叫出名字，而这恰恰是要点所在：man 手册页的作者们，在 Stack Overflow
上回答过某个冷僻 `tcsetattr` 问题的那个人，多年前在别的项目里报告过
locale 小数逗号 bug、让这个项目知道要防范 `LC_NUMERIC` 的那个人，RFC 的
评审者们，翻译者们，在奇奇怪怪的机器上测试候选版本的人们。他们没有一个是
巨人。合在一起，他们就是大地。一个只把功劳记给巨人的项目，是误解了大地
从何而来——而一个希望有所作为的项目，多半应当立志加入这片土丘：去成为
别人那平平无奇却可靠的地基。

## 高山，与大海

井の中の蛙大海を知らず、されど空の深さを知る——「井底之蛙不知大海，
却知天空之深。」

这句谚语两面开刃，两道锋刃在这里都很要紧。有深度而无广度，便是那口井：
这个项目攀登着自己的山——一个语言标准、一个平台家族，彻底地精通。有广度
而无深度，则是游客眼中的海。真正的纪律是两者都刻意为之：在陌生代码库上的
自用实战（那些催生了十几个里程碑的 zigodot 会话）；把以英语为中心的假设
逼到明处的本地化工作（M127 的宽字符工作之所以存在，是因为日文文本打破了
行编辑器对「一列」的理解）；还有追问「当你看不见时这个界面是什么样」的
无障碍工作。

我们必须去探索，才能改变自己的视角。路线图里每一个真正好的里程碑，都能
追溯到一次视角的转换——去运行这个工具而不是编写它，去读遥测数据而不是
信任设计，把它交给一个学习者而不是一个专家。高山教人手艺；大海教人谦卑；
而一口诚实照料的井，教人认识天空。一个为学习而生的工具，应当由仍然愿意
学习的人来建造——并且在它力所能及之处，自己也成为其中一员。
