# jichi

### どこにいて、どこへ向かい、どう作られたか

---

# どう作られたか

- **ビッグバンではなく、マイルストーン。** M1（骨組み） → 着実な機能の登り →
  今日の **M173**、6つのフェーズにわたって（基盤 → プロトコル → 自律 →
  堅牢化 → リリース → リリース後の深化）。
- 各マイルストーンは焦点を絞った計画；設計 + 含意は `docs/ROADMAP.md`（上部に
  **テーマ別インデックス**つき）に、新規の作業には `docs/proposals/*.md` に記録される。
- すべてのマイルストーンは**テスト**と**警告ゼロ**を伴って着地する——スイートは
  **11,000+チェック**で、各機能とともに成長し、判定ゲート付きの `make ci` の背後にある。

---

# 機能マップ（すべて出荷済み）

- **コアとコンテキスト：** ループ、2つのプロバイダ、圧縮、キャリブレーション、
  プロンプトキャッシュ。
- **編集：** 耐性のある/ファジーなパッチ、アトミックな複数編集、統一 diff。
- **知識：** ハイブリッド RAG（BM25 + 埋め込み + rerank）、ドキュメントインデックス、
  PDF、RSS。
- **自律：** エンベロープ（予算/検証/編集スコープ/ジャーナル）、スナップショット、rewind。
- **スケール：** サブエージェント（2階層）、並列 worktree、ウォームなデーモン +
  ワーカープール。
- **統合：** MCP クライアント、ACP サーバ、LSP ナビ + リファクタ、エディタ。
- **メディアと音：** 画像/音声生成、文字起こし、再生/録音。
- **安全：** パスフェンス、特権コマンドゲート、運動ゲート——すべて監査される。

# 自律運用アーク（M157–M162）

監督なしの実行はいまや**上限付き、観測され、ゲートされ、操舵され、問い合わせ可能**：

| バンド | 何が着地したか |
|---|---|
| **M157** ループ | タスクキュー上の tmux/systemd/cron スーパーバイザ + 参照パック |
| **M158** 観測可能性 | `runs` / `audit` リーダー；`doctor --unattended` ゲート；docs↔flags リント |
| **M159/M162** 制御 | 実行中の unix ソケット：`status` / `inject` / `pause[--extend]` / `resume` / `abort` |
| **M160** 機械可読 | `runs`/`audit` 向けの `--since` ウィンドウ + `--output json` |
| **M161** 来歴 | `runs` がオペレータに**操舵された**実行を示す |

すべての介入は痕跡を残す；すべての痕跡にはリーダーがある。

---

# 物理世界への到達（M163）

jichi をロボットの**熟慮する頭脳**として——センサ、アクチュエータ、音、フリート：

- **デバイスはツール**（JSON を話すユーザーツール / MCP サーバ）；jichi はデバイス
  ライブラリをリンクしない（`pdftotext` のようにシェルアウト）。
- **運動ゲート**——質量/エネルギーを動かすものはすべて `kinetic: true` で、
  **権限判定より下位**でゲートされる（一律の自動承認では満たせない）、E-stop には
  allowlist 優先、シェルバイパスは影で照合、常に監査。
- **サウンド I/O**——設定されたコマンド経由の `play_audio` / `record_audio`。
- **正直なスコープ：** jichi は**秒スケール**の層である；反射と本物の E-stop は
  その下のファームウェアにある。シミュレータに対して実証済み；ハードウェアは先送り。

# ドッグフードで学んだこと

`docs/ANECDOTES.md` より——それぞれが durable な教訓を教えたバグ：

- 観測可能性はスナップショット/ロールバックの爆発半径の**外**に置け。
- 予算の枯渇は**破棄**ではなく**停止**すべき——検証し、そして緑を保て。
- 「それはできない」は、できないことではなく、ツールの**広告**が欠けていることが
  多い（toolProfile ゲート）。
- **ログの末尾ではなく、コミットを判定ゲートせよ**——緑に見えるコミットがかつて
  赤いスイートを隠していた（ANECDOTES #17）；コミットはいまや `make ci && …` である。

# どう作られたか——4つの提供モデル

**同じ M1–M173 スコープ**に対する人間工数（人月；`docs/PROJECT_TIMELINE.md` 参照）：

```
AI-assisted (1 dev + AI)  |  ~1    (actual -- ~5 weeks, 19 active days)
Expert solo               |####################  ~21   (~20-26 months)
Team of ~6                |######################################  ~40  (~5-6 months)
Junior solo               |#########################################################  ~60  (~5-6 yrs)
```

AI 支援のバーは**人間**の監督時間（設計、レビュー、操舵）である——モデルの計算は
含まない。教訓は生の速度ではない；*人間の時間がどこへ行くか*である。

---

# 人間が実際に何をしたか（AI 支援）

開発者はほとんど C を書かなかった。希少な資源は**スタックの上方**へ移った：

- **指揮 + 要件**——次のバンドを選ぶ（約30%）。
- **設計レビュー**——コードの前に各 `docs/proposals/*.md` を承認（約25%）。
- **差分のレビュー + 実行中の操舵**——誤った前提を捉える（約25%）。
- **順序付け + 優先順位**（約12%）· **CI の検証**（約8%）。

> AI は*実装 + テスト + ドキュメント*を圧縮した；**設計と監督は人間に残った——
> そして品質の上限を定めた。**

---

# 次に向けての指針

1. **まず正しさ、次にコスト。** 積極的に検証せよ；赤だけをロールバックせよ。
2. **小さなサーフェスを組み合わせる。** 新機能は既存のチョークポイントを再利用する。
3. **すべてをオフラインでテスト可能に。** 純粋コア + 薄い I/O シェル。
4. **ログから学ぶ。** エージェント自身のテレメトリがロードマップの入力である。
5. **新規性には提案を。** コピーする参照がない → まず書いて設計せよ。
