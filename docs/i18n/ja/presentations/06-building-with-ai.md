# マイルストーンループ（再利用可能な成果物）

```
requirement  ->  design (seam + pure core + thin shell; often a proposal)
             ->  implement in C89
             ->  tests (pure-core unit + e2e/PTY smoke)
             ->  gate: -Werror + ASan/UBSan + valgrind + e2e  --(red)--> implement
             ->  docs + ROADMAP note
             ->  scoped, verdict-gated commit  ->  (next)
```

約160のマイルストーン、それぞれが小さく設計されたユニット。履歴が物語として読める
のは*この規律のおかげ*である——そしてそれが、AI を378コミットにわたってリグレッション
なく正しく保ったものだ。

# 同じスコープを提供する4つの方法

同じ **M1–M173** スコープに対する人間工数（人月、中央値）：

```
AI-assisted (1 dev + AI)  | ~1    <- actual (~5 weeks, 19 active days)
Expert solo               |#################### ~21   (~20-26 months)
Team of ~6                |###################################### ~40  (~5-6 months)
Junior solo               |######################################################## ~60 (~5-6 yrs)
```

- **AI 支援** = *人間*の監督時間（設計 + レビュー + 操舵）；モデルの計算は含まない。
- **チーム**は熟練ソロより*総*工数は多い（調整コスト）が、*カレンダー*ははるかに
  少ない——工数対スケジュールのトレードオフ。
- **初級者**は単なる遅さではなく、完成度のリスクを伴う：いくつかのサブシステムは
  メンターシップなしにこの品質へ到達するのが難しい。

# 人間の時間はどこへ行ったか

```
Direction + requirements (what to build)      ##############  30%
Design review + approving proposals           ############    25%
Reviewing diffs + steering mid-run             ############    25%
Deciding priorities / sequencing bands         ######          12%
Verifying results / reading CI                  ####            8%
```

開発者は**ほとんど C を書かなかった**。価値は*スタックの上方*へ移った：次のバンドを
選ぶ、設計を承認する、誤った前提を捉える、実行を一時停止する。

---

# なぜ衛生が*より*重要だったか、そうでなくなったのではなく

**チーム**をスケールさせるのと同じ規律が、**AI 支援**を信頼できるものにした：

- **引き締まったマイルストーン** → レビュー可能なユニット、クリーンな履歴。
- **コードの前の設計メモ** → 人間が*意図*を、安価に、まず review する。
- **純粋コアのテスト可能性** → 10,000+のオフラインアサーション；高速でハーメティックな CI。
- **厳しい品質ゲート** → リグレッションを即座に捕捉；高いコミット率が安全。
- **ユニットごとのドキュメント + コミット** → 作業が可読で再開可能。

> AI はエンジニアリングの規律を置き換えなかった——それへの**リターンを高めた**。

---

# 正直な限界

- 3つの人間モデルの**人月**の数値は見積もり（±40%）であり、納品スコープからの
  ボトムアップであって、測定された実行ではない。
- **AI 支援**の数値は直接測定された唯一のもの（カレンダー + 稼働日）だが、*人間*の
  時間だけを数える；**モデルの計算は**トークンで支払われる**実在のコスト**である。
- **参照実装**（Continue CLI）が P0–P4 の要件リスクを削減した；新規の P5 バンドには
  それがなかった——だから各バンドは提案で始まった。
- 1つのプロジェクトは1つのデータ点である。転用可能な主張は普遍的な倍率ではなく、
  **手法**である。

# 要点

**AI 支援は実装、テスト、ドキュメントを圧縮する。設計と監督は人間に残る——そして
品質の上限を定める。**

節約した時間を、いまや最も重要なところに投資せよ：*何を*作るかを決めること、そして
*結果が正しいかどうか*を判断すること。
