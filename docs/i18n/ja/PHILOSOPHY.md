# jichi の哲学

このリポジトリのドキュメントの大半は「どうやるか」を語る。このページは「なぜか」を
語る——AI コーディングエージェントを C89 でゼロから再実装するという営みの背後に
ある原則と、この企てが負っている恩義について。これはエッセイであって、リファレンス
ではない。[CONTRIBUTING.md](../../../CONTRIBUTING.md) のような規範性は、ここには
一切ない。ただ、もしある設計判断が恣意的に見えたなら、その判断が下された枠組みが
ここにある。

## 温故知新

『論語』にいう——故きを温ねて、新しきを知る。

このプロジェクトについて誰もがまず抱く疑問は、Rust と TypeScript の時代に、なぜ
C89 なのか、だろう。答えは懐古趣味ではない。C89 は、現存するプログラミング言語
標準の中で最も広く実装されているものだ。これに忠実なプログラム——`//` コメントを
使わず、宣言はブロック先頭に置き、`long long` を避け、文字列リテラルは 509 文字
未満に分割する——は、npm エコシステムが名前すら聞いたことのない機械でもコンパイル
できる。十年前の研究室のパソコン、大学の共用ログインホスト、予算のない教室の
シングルボードマシン。制約こそが機能なのだ。「学びのための」エージェントツールは、
学ぶ者の機械で動かなければ、ほとんど価値がない。

もう一つ、より静かな理由がある。計算機の世界で最も新しいもの——コードについて
推論する大規模言語モデル——には、我々の手元にある最も古い規律がよく適うと分かった。
上限を定めたバッファ、明示的な所有権、例外ではなくステータスコード、パイプと
プロセスで組み合わされる小さな道具たち。このエージェントループは、1985 年の UNIX
プログラムがそうしたのと同じやり方で fork し、パイプでつなぎ、`select` する。
故きを温ねることが、新しきを築く方法だった。

## 職人気質

職人気質とは、一つの構えの名である。観客のためではなく、仕事そのものへの責務と
して練達を追い求めること。職人は、客が来ようが来まいが、仕事場の床を掃く。

このコードベースにおける「掃き清められた床」とは、こういうものだ。
`-std=c89 -pedantic -Wall -Wextra` での警告ゼロを常に保ち、CI では `WERROR=1` を
課す。オフラインで走る 10,000 超のユニットチェックがあり、列車の中のコントリ
ビューターでもスイートを信頼できる。プロバイダのストリーミングは、ネットワークを
呼ぶのではなく、合成した SSE イベントを流し込んで検証する。すべての `cJSON_Parse`
に `cJSON_Delete` が対応する。信頼できないバイト列に向き合うパーサには、ファジング
の層がある。どれもデモでは見えない。どれも三年目には見える。

職人の仕事には、道具が何をしたかについての正直さも含まれる。ツールのエラーは値と
して返され、決して制御フローにはならない。反復上限で止まったサブエージェントは、
そのことを自ら告げる——「[stopped at its iteration limit]」——途中までの答えを
完成品として差し出したりはしない。`docs/i18n/` 以下の日本語訳と中国語訳は、
ネイティブスピーカーがレビューするまで「下訳」と明記される。自信ありげな誤訳は、
正直に印を付けた訳よりも悪いからだ。

## 改善と守破離 — 小さな歩みと、学びのかたち

改善とは、積み重ねによる前進である。このプロジェクトに書き直しは一度もない。
あるのはマイルストーンだ——M0 の骨組みから M134 の堅牢化まで——どれも、レビュー
し、テストし、必要なら差し戻せるだけの小ささを保っている。[ROADMAP](../../ROADMAP.md)
はその積み重ねの実験ノートであり、[ANECDOTES.md](../../ANECDOTES.md) は覚えて
おく価値のある失敗を記録する。省みられた過ちは教訓になるが、忘れられた過ちは
再演の稽古になるからだ。

守破離は、どの道の弟子であれ、その上達の道筋を言い表す。型を正確に守り、型を
意図して破り、やがて型を離れる。学習機能はこの形に沿って作られている。課題
（assignments）の帯は、初学者に型を与える——課題文、評価基準、段階的なヒント——
そして学習者ティア（`learner-junior|student|senior`）は、学ぶ者が力を示すにつれて
足場を緩めていく。ここでは、エージェント自身もまた弟子である。学習／メンターの
ループは自らのテレメトリを読み、教訓を起草し、M78 以降は、古い助言の上に新しい
助言を積み上げるのではなく、時代遅れになった教訓を「訂正」する。撤回できない
教えは教条にすぎない。教訓を引っ込められるようになるまで、このループは完成
しなかった。

## 不易流行

芭蕉は門人に不易流行を説いた。芸には不変のものと流れゆくものの両方が要り、
しかも両者は根本において同じ一つの探求である、と。

このプロジェクトのアーキテクチャは、その教えの応用である。「不易」——C89、POSIX、
アリーナ、`jc_status` の契約、そしてエージェントが決してその裏側を覗かない
プロバイダの vtable。「流行」——季節ごとに入れ替わるモデル、エンドポイント、
プロトコル。両者の境界は、流れが核を浸食しないように引かれている。エージェントは
プロバイダで分岐しない。新しいバックエンドとは新しい vtable のことであって、
新しいエージェントのことではない。だからこそ、フロンティア API と話すのと同じ
バイナリが、机の脇の llama.cpp サーバに対しても動く。そして、その両方が入れ
替わった後でも、なおビルドできる。

## 侘び寂び — 正直な限界の美しさ

侘び寂びは、不完全なもの、無常なもの、未完のものに値打ちを見いだす。ソフトウェア
の文化はおおむねその逆を装うが、このコードベースは装うまいとしている。トークン
推定はバイト数によるヒューリスティックで、楽観に振れることが「分かっている」——
だから M77 は、持ってもいない精度を主張する代わりに、モデルごとに実測へと較正
する。予算はランを思考の途中で打ち切る——だから M80 は、完全でなかったことを
咎めて成果を焼き捨てるのではなく、途中までの仕事を残すことを学んだ。すべての
バッファには上限があり、すべてのキャップには名前があり、出力が切り詰められた
ときには、切り詰められた旨がそこに記される。限界を認める道具は、その限界の内で
信頼できる。限界を隠す道具は、どこにおいても信頼できない。

## 巨人と、小人たちの積み重ね

我々は巨人の肩の上に立っている——そして、それと同じくらい確かに、小人たちの
積み重ねの上にも立っている。名の残らない、無数の小さな貢献のことだ。どちらの
恩義も本物であり、このプロジェクトはその双方に敬意を払う。

巨人の名を挙げるのはたやすい。C と、それを 1989 年に世界中が拠って立てるものへと
凍結した委員会。UNIX と POSIX。我々の誰が一生に出会う人数よりも多くの人類のために
バイトを運んできた libcurl。ベンダリングされた cJSON の API 設計。スナップショット
とワークツリーの機構を静かに支える git の配管（plumbing）。Language Server
Protocol、Model Context Protocol、Agent Client Protocol——いずれも、私的な優位を
公的な標準と引き換えにした寛容の行為である。この CLI が再実装する
[Continue](https://continue.dev)。その設計は、このかたちが作るに値することを
証明した。そして、ループに話し相手を与える API を提供するモデルプロバイダたち。

小人たちの名を挙げるのは難しい——そして、そこが肝心なところだ。man ページの
著者たち。`tcsetattr` にまつわる一つの晦渋な質問に答えた Stack Overflow の回答者。
何年も前に、どこか別のプロジェクトでロケールの小数点カンマのバグを報告し、
おかげでこのプロジェクトが `LC_NUMERIC` を防護すべきだと知ることになった誰か。
RFC の査読者たち、翻訳者たち、風変わりな機械の上でリリース候補を試した検証者
たち。その一人ひとりは巨人ではない。だが束になれば、彼らこそが地面である。巨人
にしか謝辞を捧げないプロジェクトは、地面がどこから来るのかを取り違えている——
そして、意味あるものになろうと望むプロジェクトが目指すべきは、おおむね、その
積み重ねに加わることだ。誰かにとっての、取り立てて語られることのない、しかし
頼れる土台になることだ。

## 山と、海と

井の中の蛙大海を知らず、されど空の深さを知る。

この諺は両刃であり、ここではその両方の刃が意味を持つ。広さなき深さは井戸である。
このプロジェクトは自らの山を登る——一つの言語標準、一つのプラットフォーム系統を、
徹底して修める。深さなき広さは、観光客の海である。要諦は、その両方を意図して
行うことにある。よそのコードベースに対するドッグフーディングのラン（十余りの
マイルストーンを生んだ zigodot のセッション群）。英語中心の思い込みを白日の下に
引き出すローカライゼーション（M127 のワイド文字対応は、日本語のテキストがライン
エディタの「桁」の観念を壊したからこそ存在する）。インターフェースが見えない
とき、それはどのようなものかと問うアクセシビリティの仕事。

視点を変えるためには、探検しなければならない。ロードマップの中の本当に良い
マイルストーンは、どれも視座の転換にさかのぼれる——道具を書くのではなく走らせる
こと、設計を信じるのではなくテレメトリを読むこと、熟練者ではなく学ぶ者の手に
渡すこと。山は技を教え、海は謙虚さを教える。そして井戸は、正直に守られるなら、
空を教える。学びのための道具は、いまなお学ぶ意志のある人々の手で作られるべきだ
——そして、できることなら、その道具自身もまた、学ぶ者の一人であるべきだ。
