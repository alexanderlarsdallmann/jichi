# Does the craft section earn its tokens? — A/B on a 31B local model (M318)

**Date:** 2026-08-06 · **Model:** `jlu/gemma-4-31b-it` (HRZ, 32k) — *the finding is about
this model* · **Pre-registration:**
[`proposals/2026-08-craft-ab.md`](../proposals/2026-08-craft-ab.md) (metrics and probe fixed
before any run) · **Verdict: no measurable benefit on this model; default now off under
`--lite`.**

---

## A — Cost. Exact, no model involved.

```
craft on   system prompt ~10329    craft section ~385
craft off  system prompt  ~9943    (absent)
```

**329–386 tokens on every model call**, depending on whether project rules are loaded — 4%
of this repository's prompt, and **the largest single part of a graded attempt's prompt**
(~329 of ~626, M312). Not in doubt.

## B — Outcome on graded tasks: 18 runs, 18 passes, both ways

Everything held fixed except `craft` (`--tool-profile core`, `repoMap: false`, same budget).
Three runs per cell; input tokens are the model's own `prompt_tokens`.

| Task | craft | calls (3 runs) | input tokens (3 runs) | sys/call | result |
|---|---|---|---|---|---|
| `00-hello` (1 pt) | **on** | 4 / 4 / 4 | 9.2k / 9.2k / 9.2k | 827 | 3× PASS |
| | **off** | 4 / 4 / 4 | 8.0k / 8.0k / 8.0k | 498 | 3× PASS |
| `06-make-the-test-pass` (3 pt) | **on** | 8 / 9 / 8 | 24.1k / 27.6k / 24.1k | 827 | 3× PASS |
| | **off** | 8 / 8 / 6 | 21.7k / 20.3k / 14.7k | 498 | 3× PASS |
| `10-design-before-code` (3 pt) | **on** | 6 / 10 / 11 | 19.5k / 44.4k / 49.8k | 827 | 3× PASS |
| | **off** | 5 / 5 / 10 | 14.0k / 14.0k / 39.1k | 498 | 3× PASS |

**Pass rate: identical (18/18).** Including on the *design* task — which is the pointed
result, and exactly what the pre-registration predicted would happen and why: task 10's spec
lists the five section headings its grader greps for, so it measures instruction-following,
not an instilled habit.

**Cost: +15% on `00-hello`, +19% median on `06`.** On `00-hello` the entire difference *is*
the prompt overhead (4 calls × 329 ≈ 1.3k ≈ the observed 1.2k) — same calls, same path.

**On `10-design-before-code` the difference is behavioural, and the variance swamps it.**
Medians say +217%, means say +69% (37.9k vs 22.4k), and the raw runs are 19.5/44.4/49.8
against 14.0/14.0/39.1. With n=3 and that spread, the only defensible statements are: craft-on
took **more calls on every ranked position** (6/10/11 vs 5/5/10), and it cost more. Whether
that extra work made a *better* design is not something this grader can say — it checks
structure, and both conditions met it every time.

## C — The under-specified probe: no observable difference

The pre-registered fair test, since B's tasks all state their deliverable. One prompt, no
deliverable named, fresh git workspace per run, three runs per condition:

> "The note-taking script in this folder appends lines but never rotates the file. Deal with
> it."

| Proxy | craft on | craft off |
|---|---|---|
| Wrote an unprompted design/explanatory file | 0 / 3 | 0 / 3 |
| Final answer names a rejected alternative | 0 / 3 | 0 / 3 |
| Wrote a test for the change | 0 / 3 | **1 / 3** |
| Answer length (bytes) | 857 / 1325 / 978 | 807 / 911 / 1070 |

**Nothing the craft section asks for appeared in either condition.** The one run that wrote a
test was `craft: false`.

The answers are near-identical in substance — read, edit, verify with an ad-hoc test, clean
up, self-review. Both conditions produce that, because the **base persona** already says to
read before editing and make minimal targeted edits, and AUTO-mode **self-review** (M39)
already produces the review paragraph. The craft addendum is competing with instructions the
model already had.

*Instrument check:* the proxies were verified by reading the raw answers rather than trusting
the greps — a zero from a broken grep looks exactly like a zero from a real null (the lesson
of M310–M316, applied to a measurement instead of a report).

## Decision

**`craft` now defaults OFF under `--lite`**, joining `repoMap` / `references` / `markdown` as
a resource-heavy default the lean tier drops (M20b/M20c). An explicit `craft` key still wins
**in both directions**, and that is unit-tested.

**The default stays ON everywhere else**, and that is a deliberate limit on what 18 runs of
one 31B model can license. The section's claimed value is about *larger* models (which have
window to spare) and *larger, vaguer* tasks (where a design note is the deliverable nobody
asked for) — neither of which was tested here, and neither of which a `--lite` run is doing.

**What would change my mind in the other direction:** the same A/B on a frontier model with a
task whose deliverable is genuinely unstated and whose output a human grades. If the section
produces a better design *there*, its home is "on by default, off on small models" — which is
exactly what shipped, so that experiment can only strengthen the current setting.

## What this does not say

- **Nothing about frontier models.** Not tested; the title says so.
- **Nothing about candour.** "Say plainly what is unverified" is the half of the section I
  most believe in and cannot measure. No mechanical probe I have can score a model's honesty,
  and inventing one would be worse than admitting the gap.
- **Nothing about human readers.** A design note's value is largely to the *next person*, on
  a timescale no single run can see. A negative result on a 3-call task is not evidence
  against writing designs; it is evidence that this model does not write them because it was
  asked to, in this prompt, at this size.
