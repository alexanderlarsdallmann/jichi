# WIP limits — finish before you start

A WIP (work-in-progress) limit caps how many things you are actively working on
at once. It is the most counter-intuitive and most useful project habit, and for
a solo worker it is close to the whole game.

**Why fewer-at-once is faster overall:**

- **Context-switching is expensive.** Every time you jump between tasks you pay a
  re-orientation cost. Three tasks half-done cost more total time than three done
  one after another.
- **Half-done work is worth nothing.** A feature 90% built ships nothing, teaches
  little, and motivates less than one small thing *finished*. Value arrives at
  `Done`, not at `Doing`.
- **Too much in flight hides blockers.** When one task stalls you just switch to
  another, so the stall never gets confronted — it just quietly rots.
- **It caps the mental load.** Ten open loops is exhausting; one is calm. Calm
  finishes projects.

**How to actually keep it (the hard part):**

1. Pick a number. Solo: **1** in `Doing` (2 only if you are genuinely blocked and
   waiting). Write the limit right on the board heading.
2. Before starting anything new, ask: *can I finish what's already in Doing
   first?* Usually yes.
3. When you feel the pull to start something shiny, put it in `Todo` (or a
   `Later` list) — capture it so you can let it go — and get back to finishing.
4. If `Doing` keeps overflowing, that is the signal, not the exception: something
   is blocked or too big. Fix *that*, do not raise the limit.

The mantra: **stop starting, start finishing.**
