# Definition of done

"Done" is where projects go to die when it is left undefined. A self-learner's
project with no clear finish line runs forever, because there is always one more
tweak — and "one more tweak" is not a plan, it is a trap.

**A good definition of done is a checkable condition**, not a feeling:

- Bad: "when it's good enough", "when I'm happy with it". Unfalsifiable; you can
  always find a reason it is not there yet.
- Good: "when a stranger can clone it and run the example without asking me",
  "when the three core screens work and the tests pass", "when the report answers
  the question with the caveats stated". You can look at it and say yes or no.

**Define done at two levels:**

1. **Per project** (in the charter): the condition that means the whole thing is
   finished. Decide this *before* you start — it shapes everything, and it is
   almost impossible to set honestly once you are attached to the work.
2. **Per card** (on the board): what "done" means for this specific card. If you
   cannot say when a card is finished, the card is not ready to work — sharpen it
   first.

**The test:** could someone else look at the result and agree it is done, without
you explaining? If yes, your definition is checkable. If it depends on your mood,
it is not a definition — it is a feeling wearing a definition's clothes.

Deciding what "good enough" means *up front* is also what frees you to stop
polishing and ship. Done is a decision, and you make it before you need it.
