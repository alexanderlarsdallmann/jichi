description: A retrospective — what went well, what didn't, what to change — so a solo worker actually improves project to project.
---
Run a **retrospective**, recorded in `RETRO.md` (append a dated section for a
milestone, or write it fresh at project end). This is how a self-learner turns
one project's lessons into the next project's habits — the improvement loop a team
gets from working together.

Guide the user through, and write down:

1. **What went well** — what worked that you want to keep doing. Be specific;
   "planning helped" is weak, "breaking the big card into three made it move" is
   useful.
2. **What didn't** — where you got stuck, over-committed, drifted, or under-
   estimated. Be honest, not harsh — this is data, not a verdict.
3. **Estimates vs reality** — did it take longer than you thought? By how much?
   (It almost always does. Noticing by how much is how you get better at guessing.)
4. **One or two changes to try next time** — small, concrete, actionable. Not "be
   more disciplined" — "set a WIP limit of one", "define done before starting".

Keep it short and kind. A retro that only lists failures teaches you to dread
them; a retro that names one thing to try teaches you to improve.
