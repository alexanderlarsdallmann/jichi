---
description: Write a one-page project charter — what, why, and what "done" means — before any work starts.
---
Write or refine `CHARTER.md`: a **one page** answer to what this project is and
when it is finished. A project without a charter drifts; a self-learner's project
without a defined "done" runs forever.

Ask the user (or refine what they give you) until you can fill all of:

1. **What** — the project in two plain sentences a stranger would understand.
2. **Why** — the reason it matters to *you*. If you cannot say why, reconsider
   whether to do it at all.
3. **Definition of done** — the checkable state that means "finished". Not a
   feeling ("when it's good") — a condition ("when a stranger can install it and
   run the example", "when the three core screens work"). This is the most
   important line; do not let it stay vague.
4. **Explicitly out of scope** — a short "not doing / later" list. Naming what you
   are *not* doing is how you protect the project from scope creep.
5. **A rough size** — days? weeks? If it is "months", it is probably too big for a
   first solo project; consider carving out a smaller version.

Keep it to a page. Offer to run the read-only `scope-reviewer` — a charter with no
definition of done is the #1 way a solo project never ends.
