---
description: Cut the design down to something actually buildable — the single most useful game-design skill for a beginner.
---
Help the user shrink their game to a scope they can actually build and finish.
Scope creep is the reason most first games are never completed; cutting is the
skill this command teaches.

Read the current design (`GDD.md`, `mechanics/`) and do this honestly:

1. **Estimate the build.** For each feature/mechanic, a rough "how hard to build"
   (small / medium / large / do-not-know). "Do-not-know" counts as large.
2. **Find the core.** Which *one* mechanic carries the core fun? Everything else
   is negotiable.
3. **Propose a cut list.** The smallest set that still has the core fun — usually
   far smaller than the learner expects. Be specific about what goes and what
   stays, and reassure: cut features are not deleted, they are a "later" list.
4. **Define "done" for version 1.** A single sentence: when is the first
   playable version finished? Without this, a project never ends.

Write the result into the GDD's "smallest playable version" section. Frame it
kindly but firmly: a small finished game teaches more than a huge unfinished one.
